# wildid — project conventions
- Python 3.14 (minimum 3.12), managed by uv. Run everything via `uv run`. Never pip into the global interpreter. Python always comes from uv, never from the machine, on every system (owner, 2026-11-15): `python-preference = "only-managed"` in `pyproject.toml` is the one place that says so. It reaches an installed copy because both installers ship that file and every uv call of their scripts names the project (`--project`): keep it that way; a test checks it.
- Model inference only through pybioclip APIs (TreeOfLifeClassifier, create_taxa_filter, apply_filter). Do not reimplement CLIP scoring.
- Default model is `bioclip-2`: the published BioCLIP 2.5 TreeOfLife embeddings have no reptiles (docs/decisions/0001-bioclip-25.md). Keep 2.5 selectable; do not flip the default without new evidence.
- Never demosaic RAW files in the predict path; use embedded previews. Demosaic is a logged fallback only.
- No network in tests. iNat calls go through geo.py with the disk cache; tests mock HTTP.
- Offline-first: `wildid PATH` runs with HF_HUB_OFFLINE=1 set before importing bioclip/open_clip/torch and never downloads a model. Only `wildid prefetch` downloads. Geo fetches are cache-first with a 5 s connect timeout; a cached entry of any age beats a network call.
- Geo filtering is species rank by default; `--geo-rank genus` is the only wider mode. Never filter TOL by order/family. iNaturalist is the only source of species lists; GBIF is used solely to reconcile names (synonyms.py), and only from `wildid prefetch`.
- Auto-geo (`--geo-auto`, ADR 0006): positions resolve to iNat places from cached 0.25° cells only, in the CLI and the daemon alike; `wildid prefetch --gps-from` and `POST /prefetch` are the only online paths. A photo without GPS or in a cell not prefetched runs unfiltered (the latter flagged for review, and counted in the run's summary), never against a guessed place. Country and region are the only levels.
- Optional stages: the detector (MegaDetector v6 via ultralytics) and SpeciesNet load pickled checkpoints that `wildid prefetch` fetched with pinned SHA-256; `env.py` keeps `TORCH_FORCE_WEIGHTS_ONLY_LOAD=0` and `YOLO_OFFLINE=true` before any import. Do not add the `speciesnet` or `PytorchWildlife` packages (dependency bloat, typer downgrade); keep loading the published files directly. The resize before the detector stays ultralytics' own by default, on every system; the exact resize (`--crop-exact`, `crop_exact` in a `/classify` request, the checkbox in the plug-in) is an option, off everywhere, and making it a default needs a new owner decision (owner, 2026-11-15; ADR 0003 §1). Whether it makes a Mac and a PC agree is not measured (backlog item 13 in `species-id-mvp-plan.md`): until then every text about it says "meant to".
- Precision: TF32 by default on CUDA, fp16 opt-in, bf16 rejected (measured, ADR 0003). Measure before changing. On MPS (Apple Silicon) `auto` is fp32, tf32 (a CUDA mode) falls back to it, and fp16 is the same opt-in as on CUDA (owner, 2026-11-15, after measuring it there: ADR 0003). The Lightroom plugin's server stays on `auto` on every platform, so fp32 on a Mac: fp16 buys only 1.4 to 1.6 times on the plugin's path, and making it a default anywhere needs a new owner decision.
- The loader pre-shrinks images with the model's own transform objects (`model.make_preshrink`) so pybioclip's transform is an identity; keep it that way and re-measure top-1 agreement on `sample-jpg/` when touching it or the loaders (ADR 0003 §5).
- Model + label data load once per process. No per-image model calls.
- Keep the CLI contract in species-id-mvp-plan.md §4 stable; add flags, do not rename.
- Decisions live in docs/decisions/*.md (ADR style). Update when a locked decision changes.
- Output must be UTF-8 safe on Windows.
- SI units only in any user-facing text.
- Real test photos: `sample-jpg/` (863 JPG exports) and `sample-arw/` (152 ARW + 5 DNG + 3 TIF copies), both git-ignored and owner-provided, one folder per species or trip (folder name = ground truth or place), for accuracy, geo and sidecar checks; `tests/fixtures/*.ARW` for RAW tests. Never commit, move or delete them.
- Lightroom integration (ADR 0005): keyword/review policy lives in `keywords.py` only — the Lua plugin is a dumb writer of `suggested_keywords`. One result schema (`results.py`); bump `protocol` on breaking changes and ship plugin + engine together.
- `wildid serve` stays stdlib-only, binds 127.0.0.1 and requires the serve.json bearer token on every request; /classify never fetches geo lists (POST /prefetch is the only online endpoint).
- XMP sidecars (`--write-xmp`) are pre-import, RAW-only (never DNG/JPEG — they embed XMP), never touch photo files, and `merge` may only append subject entries + wildid provenance.
- macOS (ADR 0008; the owner said "build macOS version now" on 2026-11-14, which lifted the 2026-10-28 paper-only rule): Apple Silicon only, macOS 14+, `--device mps`, fp32 by default; the download is `installer/macos/` (a zip with `install.sh`; no `.pkg`, no `.dmg`, no root). The build plan (`docs/PLAN_MacOS.md`) was executed and removed on 2026-11-15 (owner); ADR 0008 is the record, and no change log of macOS impact is kept any more. **The owner declared macOS available on 2026-11-15 ("it's there now"):** the website and the READMEs present it as available, with no "coming soon" anywhere, and quote the figures measured on the one Mac (`docs/acceptance.md`). The acceptance in `docs/acceptance-macos.md` is still open and still to be run: the plug-in has not been run in Lightroom Classic on a Mac, the real install is the owner's, and no release carries the Mac zip yet (`website/TODO_WEBSITE.md`). Never write that something was tested on a Mac when it was not: the site's Lightroom steps for macOS come from the code and the Windows run. Requirements state only what was measured (owner, 2026-11-15; no smaller Mac is available; ADR 0008 decision 8): name the one Mac measured, a MacBook Pro with an M5 Pro and 48 GB, say that no other Mac has been tried, and never state a minimum memory or what a smaller Mac needs or does. Assume a photographer's Mac has no Homebrew, no Python and no developer tools (owner, 2026-11-15; ADR 0008 decision 6): `install.sh` and the launchers call only what macOS ships (never `python3`, `git`, `make`), Python is uv's own by the project setting (first bullet), and the CI smoke installs in a bare environment; tests in `tests/test_installer_macos.py` keep all three. Keep the three platforms on one torch version (`constraint-dependencies` in `pyproject.toml`) and re-lock only with the uv version CI pins (a newer uv rewrites the lock's `revision`).
- Licence (ADR 0007, 2026-11-04): the whole repository is AGPL-3.0-or-later (`LICENSE`, verbatim GNU text — never edit it), free, public GitHub repo, releases from that same repo so the installer sits next to its source. A new dependency must be redistributable alongside AGPL code; never add one that is not.
- Website (`website/`, 2026-11-13): hand-maintained static HTML, one stylesheet, no JavaScript, no build step, nothing loaded from other servers. `.github/workflows/pages.yml` publishes it to GitHub Pages (the repository is public and Pages is switched on since 2026-11-15, so a push to `main` that changes `website/` publishes the site); at deploy it only puts the real address in place of the `https://WILDID-SITE-URL.invalid` placeholder, which must stay in the pages, and leaves `README.md` and `TODO_WEBSITE.md` out. Every claim on it must match the READMEs, the plugin and `docs/acceptance.md`: when a change alters what the site says (requirements, numbers, dialogs, setup steps, licence), update the page in the same commit. Before pushing a site change, check that internal links and anchors resolve and open the page once; no test run. Never invent a figure for it.
- Public repository (owner, 2026-11-15): everything pushed to `main` is published at once, and neither a later commit nor a forced push takes it back, so what must not be public is caught before the push. In every file and commit message the owner is `Trogious`, or "the owner": no other name of his. Never commit an account name, a host name, a home folder written out (write `~/…`), a network address, a token or key, or photo metadata; look at what a new image or other binary file carries before adding it. Documents name no commit, CI run, tag or release that this repository does not hold: describe the event instead ("the second CI run", "version 0.3.1"). Before each commit, search the tree for all of this, binary files included (`git grep -a -i`).
- No Claude tags or inscriptions, in commit messages or anywhere else (owner rule, 2026-10-28 for commits and PR descriptions; widened by the owner on 2026-11-15 to everything): never any Claude attribution, tag line, signature or "made by" note — no `Co-Authored-By: Claude …`, no "Generated with Claude Code", nothing of the kind — in commits, PR descriptions, code, comments, docs, the website, issues, release notes or any file written for this project, inside the repository or outside it. A commit's subject and body describe the change only. Claude is never a commit's author or committer either (owner, 2026-11-15): a session whose environment commits as `Claude <noreply@anthropic.com>` (`git var GIT_AUTHOR_IDENT` shows it) sets the owner's identity `Trog`, with the name and email of the owner's own commits, before its first commit.
- Landing work (owner rule, 2026-10-28): verify in proportion to what changed, then commit and push to main without asking. Engine code (`src/`, `tests/`): `uv run pytest`. Plugin code (`lrplugin/`): `luajit lrplugin/tests/<name>_test.lua lrplugin/wildid.lrplugin` for the eight plain-Lua tests (`lr_stub_test` needs a live daemon). CI (`.github/workflows/`) and `installer/` scripts: a syntax check only (parse the YAML, `py_compile` the Python), no test run. Anything that is not code (plans, docs, ADRs, Markdown, this file): push without running tests. Never offer, suggest or create tags or releases: the owner cuts releases and knows the tag-driven CI (release.yml). Since 2026-11-15 a pushed tag `v*` publishes a GitHub Release at once, not a draft (only a manual run with `create_release` makes a draft), so a tag is never pushed to try something out; `tests/test_release_workflow.py` runs the release step against a stand-in for `gh` instead.
